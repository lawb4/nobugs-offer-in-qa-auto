# Какую структуру данных вне языков программирования вы бы выбрали для описанной задачи?

Укажите структуру данных и объясните почему.

1. **Хранение уникальных идентификаторов пользователей**
   В системе есть список уникальных идентификаторов пользователей. Необходимо быстро проверять, присутствует ли пользователь с заданным идентификатором.

Ответ: Множество (Set), т.к. список должен иметь уникальные элементы (уникальные идентификаторы пользователей). В случае хэш-множества поиск элемента в среднем имеет постоянную временную сложность O(1). 

2. **Очередь задач для обработки**
   Система должна обрабатывать запросы в порядке их поступления. Требуется поддерживать последовательность.

Ответ: Очередь (принцип FIFO) — запрос добавляется в конец очереди, а обрабатывается с начала очереди. 

3. **Хранение ключей и значений**
   Необходимо хранить настройки приложения, где каждый параметр имеет имя (ключ) и значение.

Ответ: Словарь (Map) — коллекция пар ключ-значение как раз и решает подобные задачи, как хранение настроек приложения.

4. **Иерархия сотрудников компании**
   Требуется сохранить данные о сотрудниках в виде дерева: каждый сотрудник имеет подчинённых.

Ответ: Tree (структура данных) - связи сотрудник-подчинённый образуют иерархию. 

5. **Поиск элементов по приоритету**
   Система обрабатывает задачи, причём приоритет задачи определяет, когда она будет выполнена.

Ответ: Priority Queue. Важен приоритет элемента, т.к. следующая задача для обработки выбирается на основании приоритета.

6. **Управление друзьями пользователя**
   Требуется хранить связи между пользователями в социальной сети, где каждый пользователь может быть связан с несколькими другими.

Ответ: Graph — структура данных с элементами-вершинами (пользователями) и связями (факт "дружбы" между пользователями). 

7. **Упорядоченный список**
   Необходимо хранить список чисел в отсортированном виде, чтобы быстро находить минимальное и максимальное значения.

Ответ: Отсортированный массив. Поиск минимального и максимального значения в таком случае будет иметь константную временную сложность O(1), т.к. минимальное и максимальное значение находятся на краях массива, и к ним можно обратиться по индексу.

8. **Учет посещений страниц**
   Система должна отслеживать уникальные посещения страниц на веб-сайте и вести подсчёт общего числа посещений.
   > **Подсказка:** выбор структуры данных может быть разный в зависимости от уточнения, уникальные ИЛИ не уникальные общие посещения мы считаем.

Ответ: 
Используем Словарь, который в ключе хранит пользователя, а в значении - множество страниц. То есть, у каждого пользователя хранится множество посещённых им страниц, а общий счётчик хранится отдельно и увеличивается при каждом посещении.

Когда пользователь посещает страницу, проверяем, посещал ли он эту конкретную страницу до этого. Если нет, то добавляем данную страницу в множество и увеличиваем счётчик посещений страниц на 1. 

Если пользователь уже посещал данную страницу, то эту страницу в множество не добавляем, но счётчик посещения страниц всё равно увеличиваем на 1.

Чтобы получить число уникальных посещений всего сайта, нужно сложить размеры множеств страниц всех пользователей.

9. **История действий пользователя**
   Необходимо хранить список последних действий пользователя, чтобы можно было отменить или повторить действия.

Ответ: 2 Stack-а (принцип LIFO) — в одном стеке храним выполненные действия, а во втором - отменённые. 

Когда отменяем последнее действие пользователя, то отменяем результат действия и переносим действие с вершины первого стека во второй стек. 

Когда нужно повторить последнее отменённое действие, то выполняем действие снова и переносим его с вершины второго стека в вершину первого стека.

10. **Структура телефонной книги**
    Требуется хранить имена и номера телефонов, чтобы быстро находить номер по имени.

Ответ: Словарь (Map), где имя – ключ, а номер телефона – значение.

11. **Проверка корректности скобочной последовательности**
    Пользователь вводит строку, содержащую скобки. Нужно определить, правильно ли расставлены скобки.

Ответ: Stack (принцип LIFO) через отслеживание состояния элемента, который лежит на его вершине. Последняя открытая скобка должна закрыться первой.

При каждой встреченной открывающей скобке кладём её на вершину стека. 

При встрече закрывающей скобки проверяем, лежит ли на вершине стека открывающая скобка того же типа. Если лежит, то удаляем из стека элемент на его вершине (открывающую скобку) и проверяем строку со скобками дальше.

При чтении строки проверка завершается сразу в двух случаях:
1. Если при встрече закрывающей скобки стек пуст.
2. Если при встрече закрывающей скобки на вершине стека находится открывающая скобка другого типа.

Если ошибок до конца строки не было, то проверяем содержимое стека. Если он пуст, то скобки в строке были расставлены корректно. Если стек не пуст, то скобки были расставлены некорректно.

12. **Хранение объектов с частым доступом**
    Требуется хранить фиксированное количество элементов, которые часто изменяются, с быстрым доступом к любому из них.

Ответ: Массив фиксированного размера. В таком массиве доступ к элементу по индексу можно получить по константной временной сложности O(1).

13. **Уникальные слова в тексте**
    Дан текст, нужно сохранить все уникальные слова и определить их количество.

Ответ: Множество (Set) уникальных слов, а их количество – это размер множества.

14. **Структура электронной очереди**
    В поликлинике пациенты записываются в очередь, и каждый должен быть вызван в порядке записи.

Ответ: Очередь (принцип FIFO) – соответствие порядку записи пациентов.

15. **Список дел**
    Требуется сохранить список задач, который можно пополнять, удалять и сортировать по сроку выполнения.

Ответ: Двусвязный список. Добавление и удаление задач с конца имеет константную временную сложность O(1), т.к. список хранит ссылку на хвост. 

Поиск задачи по названию может иметь линейную временную сложность O(n). 

Если нужно ещё и удалить эту задачу или добавить новую именно после найденной задачи, то это будет дополнительно иметь константную временную сложность O(1). 

16. **Анализ частоты слов**
    Требуется определить, сколько раз каждое слово встречается в тексте.

Ответ: Словарь, где ключ – слово, а значение – число вхождений слова (ключа), включая его первое упоминание.

17. **Система рейтингов**
    Вам нужно хранить список игроков с их рейтингами, чтобы быстро находить игрока с самым высоким рейтингом.

Ответ: Priority Queue, где рейтинг выступает в роли приоритета. Эта структура данных позволит найти игрока с самым высоким рейтингом без перебора всех игроков и без удаления игрока с наивысшим рейтингом из очереди.

18. **Проверка дубликатов в потоке данных**
    Данные поступают в потоковом режиме, и нужно проверять, был ли данный элемент уже получен ранее.

Ответ: Множество (Set). Скорость проверки в случае хэш-множества в среднем будет равняться постоянной временной сложности O(1). 

При поступлении новых данных проверяем, был ли данный элемент получен ранее. 

Если да, то это дубликат, и он не добавляется во множество. 

Если такого элемента ещё не было, то добавляем его во множество, чтобы при дальнейшем поступлении данных проверить, был ли уже получен такой элемент.
